# Источники дополнительных данных

Источники дополнительных данных — необязательная четвёртая ось `humanizer_russian`.

Это **не библиотеки рецензентов**, и они не голосуют в редколлегии. Такой источник предоставляет корпусные, разговорные, лексико-прагматические, нормативные, синтаксически разобранные или исследовательские данные для `phenomenon_id`, который редактор уже рассматривает.

```text
КНИГИ/ИСТОЧНИКИ → БИБЛИОТЕКИ РЕЦЕНЗЕНТОВ → находки
КОРПУСА/СЛОВАРИ/СПРАВОЧНИКИ → ДОПОЛНИТЕЛЬНЫЕ ИСТОЧНИКИ → данные
СТИЛЬ → редакционная политика

находки + данные → РЕДКОЛЛЕГИЯ
```

## Контракт рабочего контура

Этот слой намеренно легко отключить и невозможно незаметно превратить в обязательную зависимость компактного навыка:

- `scripts/check.py` никогда не запускает дополнительные источники.
- `scripts/review.py` не запускает их без явного `--evidence ...`.
- `--evidence off` или отсутствие параметра означает ноль обращений к этому слою.
- `HUMANIZER_EVIDENCE=off` полностью его отключает.
- `PROJECT` — состояние заготовки, а не рабочего источника: такие источники нельзя выбрать явно, и они исключены из `auto` и `all`.
- в рабочем контуре допускаются только источники `OPERATIONAL`.
- сетевые источники должны иметь `enabled_by_default: false`.
- каждый рабочий источник запускается изолированно в отдельном процессе с жёстким тайм-аутом.
- на весь проход действует общий лимит времени (`HUMANIZER_EVIDENCE_BUDGET_MS`, по умолчанию 1200 мс).
- сбои и тайм-ауты по умолчанию обрабатываются как `SKIP`, отражаются в `evidence_status` и не ломают редакторскую проверку.
- `failure_policy: ERROR` допустим только для явно исследовательских сценариев.

Это означает, что недоступный корпус или API может снизить качество дополнительных данных только после того, как реальный источник переведён в `OPERATIONAL`; незавершённая заготовка не может выдавать себя за включённую возможность.

## Манифест источника

Источник описывается в `evidence/<provider_id>/provider.json` по схеме `schemas/evidence-provider.schema.json`.

Важные поля: стабильный `id`, `status`, `evidence_type`, необязательный `module_path`, `enabled_by_default`, `network_required`, `failure_policy`, `timeout_ms`, возможности и ссылки.

Состояния намеренно строгие:

- `PROJECT` — только проект или заготовка; обязан иметь `enabled_by_default: false` и не может выбираться рабочим контуром;
- `OPERATIONAL` — реализован и достаточно проверен для запуска; требует `module_path`;
- `DISABLED` — реализованный или исторический источник, намеренно недоступный рабочему контуру.

Переход из `PROJECT` в `OPERATIONAL` — отдельное явное изменение, проходящее ревью. Само появление файла модуля ничего не включает.

Предпочтительный адаптер — `evidence_v1`:

```python
def collect(text: str, context: dict, timeout_ms: int) -> dict:
    return {"evidence": [...]}
```

Рабочий контур передаёт нормализованные находки в `context`, чтобы источник мог запрашивать только относящиеся к делу явления.

## Элемент дополнительных данных

Нормализованные данные следуют `schemas/evidence-item.schema.json` и содержат `provider_id`, `phenomenon_id`, тип данных, направление, область применения, пояснение и происхождение.

`direction` — **не вердикт рецензента**. Возможные значения: `SUPPORTS_KEEP`, `SUPPORTS_CHANGE`, `CONTEXT` и `NEUTRAL`. Редакторские голоса остаются находками рецензентов. Дополнительные данные прикрепляются к совпадающим явлениям и сами по себе не меняют статус или рекомендацию редколлегии.

## Границы достоверности

Частотность не равна норме. Корпус социальных сетей не может сам по себе повысить форму до `NORM`.

Нормативный источник может подтверждать решение о норме только когда известны его область действия, версия и конкретная статья или запись.

Книга или рецензент не может ссылаться на популярность в корпусе как на основание стереть регистр, голос автора, функциональный повтор, прагматические частицы, эллипсис или информационную структуру.

## Проектные семейства источников

Сейчас в репозитории есть только проектные манифесты `current_usage`, `spoken_russian`, `discourse_lexicon`, `normative_reference` и `parsed_russian`.

Они намеренно не работают, пока не выбраны конкретный источник или API, права и условия использования, контракт запросов, стратегия кэширования, калибровочные тесты и рабочий модуль. `--evidence all` их не включает, а запрос по идентификатору завершается ошибкой вместо имитации запуска со статусом `UNAVAILABLE`.
