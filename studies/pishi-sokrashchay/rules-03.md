# Atomic rules PS-R41—PS-R60

## PS-R41 — Снижать одновременную новизну для неподготовленной аудитории
P `PROJECT_REFINED` · scope `general` · level `sentence` · automation `MODEL_ONLY` · source nodes 96,97
Trigger: Одновременно вводится несколько новых сущностей и связей.
Operation: Убрать второстепенное, разнести шаги или сначала дать общую опору.
Guard: Не вводить универсальный числовой лимит «одна мысль».
Success: Новое не требуется понять через ещё не введённое новое.

## PS-R42 — Обобщать однотипные новые элементы перед перечислением
P `SOURCE_DIRECT` · scope `general` · level `sentence` · automation `MODEL_ONLY` · source nodes 98
Trigger: Список незнакомых элементов не имеет понятной категории.
Operation: Сначала назвать общий класс/роль, затем элементы.
Guard: Не создавать ложную категорию для разнородных элементов.
Success: До списка понятно, что объединяет элементы.

## PS-R43 — Объяснять зависимые понятия по цепочке
P `SOURCE_DIRECT` · scope `general` · level `sentence` · automation `MODEL_ONLY` · source nodes 99,152
Trigger: Целевое понятие зависит от другого неизвестного понятия.
Operation: Сначала ввести ближайшую опору, затем следующий шаг.
Guard: Не разжёвывать известное подготовленной аудитории.
Success: На каждом шаге большинство опор уже знакомо.

## PS-R44 — Модель новизны строить под аудиторию
P `SOURCE_REPEATED` · scope `general` · level `document` · automation `MODEL_ONLY` · source nodes 96,99,100,150,162
Trigger: Автор считает очевидным то, что может быть новым адресату.
Operation: Определить уровень подготовки и адаптировать объяснение.
Guard: Не стереотипизировать аудиторию по возрасту/соцгруппе без данных.
Success: Объяснение не недодаёт и не пережёвывает базу.

## PS-R45 — Слабую склейку самостоятельных сообщений проверять на разделение
P `PROJECT_REFINED` · scope `general` · level `sentence` · automation `MODEL_ONLY` · source nodes 112
Trigger: Несколько самостоятельных сообщений соединены слабой связью.
Operation: Сравнить с разделением или явной логической связью.
Guard: Бессоюзие и длинное предложение сами по себе не дефект.
Success: Логические отношения яснее.

## PS-R46 — Вложенное подчинение разворачивать при потере иерархии
P `PROJECT_REFINED` · scope `general` · level `sentence` · automation `MODEL_ONLY` · source nodes 113
Trigger: Внутри незакрытой зависимости открываются новые, и каркас теряется.
Operation: Перестроить порядок или разделить на шаги.
Guard: Не считать количество союзов механически.
Success: Главная связь восстанавливается без перечитывания.

## PS-R47 — Когнитивную рамку упрощать без потери источника позиции
P `PROJECT_REFINED` · scope `general` · level `sentence` · automation `MODEL_ONLY` · source nodes 114
Trigger: «Я считаю/он сказал/мы хотим» лишь отдаляет мысль.
Operation: Сравнить более прямую формулировку.
Guard: Сохранять источник, волю, намерение, сомнение и ответственность, если они смысловые.
Success: Кто думает/хочет/сообщает и с какой уверенностью остаётся понятным.

## PS-R48 — Коррелятивы оценивать по дистанции и нагрузке
P `PROJECT_REFINED` · scope `general` · level `sentence` · automation `SOFT_SIGNAL` · source nodes 115
Trigger: Части «не только…но и», «как…так и», «если…то» разнесены так, что связь забывается.
Operation: Сблизить части или перестроить фразу.
Guard: Короткие прозрачные коррелятивы не трогать.
Success: Связанные части легко удерживаются вместе.

## PS-R49 — Парцелляцию отличать от живого эллипсиса
P `PROJECT_REFINED` · scope `general` · level `sentence` · automation `MODEL_ONLY` · source nodes 108,109
Trigger: Точка разрывает зависимость без новой дискурсивной функции.
Operation: Собрать зависимость обратно либо придать фрагменту реальную функцию.
Guard: Однословные ответы, нулевой субъект, ударный повтор и авторский ритм сохранять.
Success: Граница несёт смысл/ритм, а не только искусственную драму.

## PS-R50 — Не насаждать действие в каждом предложении
P `PROJECT_REFINED` · scope `general` · level `sentence` · automation `MODEL_ONLY` · source nodes 105,106,107,167
Trigger: Серия статических фраз действительно делает событие неясным?
Operation: Добавить действие там, где оно проясняет; состояния оставить состояниями.
Guard: Не вставлять глагол/деятеля ради формального правила.
Success: Текст естественен, фокус правильный.

## PS-R51 — Однородный ряд проверять на информационную уникальность
P `SOURCE_DIRECT` · scope `general` · level `sentence` · automation `MODEL_ONLY` · source nodes 118
Trigger: Несколько элементов дают одну и ту же информацию.
Operation: Оставить наиболее точный или развести реально разные значения.
Guard: Не удалять профессиональную типологию, ритмический ряд или доказательную детализацию.
Success: Каждый оставшийся элемент выполняет отдельную функцию.

## PS-R52 — Если различия ряда важны — раскрывать их
P `PROJECT_DERIVED` · scope `general` · level `paragraph` · automation `MODEL_ONLY` · source nodes 118
Trigger: Автор считает близкие элементы разными, но читатель не видит различия.
Operation: Разнести различия по отдельным объяснениям/примерам.
Guard: Не раздувать оттенки, которые не влияют на задачу.
Success: Читатель понимает, зачем присутствуют оба элемента.

## PS-R53 — Собирать информационный абзац вокруг доминирующей темы
P `PROJECT_REFINED` · scope `general` · level `paragraph` · automation `MODEL_ONLY` · source nodes 120,125,126
Trigger: В абзаце конкурируют самостоятельные темы.
Operation: Определить доминирующую тему; второстепенную перенести или выделить.
Guard: Не применять как норму к намеренному потоку сознания и художественной композиции.
Success: Большинство предложений поддерживает одну локальную задачу.

## PS-R54 — Проверять скелет текста по первым предложениям абзацев
P `SOURCE_REPEATED` · scope `general` · level `document` · automation `REVIEW_GATE` · source nodes 121,122,123
Trigger: Первые предложения дают прокладки вместо маршрута.
Operation: Прочитать только начала абзацев и при необходимости вынести туда тезис/пользу/действие.
Guard: Кикер, история и разговорный заход допустимы при реальной функции.
Success: По началам понятен ход информационного текста.

## PS-R55 — Финал абзаца использовать только для нового следствия
P `SOURCE_DIRECT` · scope `general` · level `paragraph` · automation `MODEL_ONLY` · source nodes 124
Trigger: Последняя фраза повторяет начало другими словами.
Operation: Удалить дубль либо дать поддержанное следствие, правило, действие или связь.
Guard: Не добавлять вывод ради симметрии.
Success: Финал добавляет функцию или отсутствует.

## PS-R56 — Цель формулировать как контролируемую помощь читателю
P `PROJECT_REFINED` · scope `general` · level `document` · automation `MODEL_ONLY` · source nodes 129,130
Trigger: Цель требует гарантированно переубедить/заставить/замотивировать.
Operation: Переформулировать как помощь понять, увидеть, сравнить, подготовиться или сделать.
Guard: Это рабочая модель книги, не универсальная теория коммуникации.
Success: Успех можно оценить без контроля чужой воли.

## PS-R57 — Задачи текста делать конкретными смысловыми ходами
P `SOURCE_DIRECT` · scope `general` · level `document` · automation `MODEL_ONLY` · source nodes 131
Trigger: Есть цель, но неясно, какие элементы ведут к ней.
Operation: Разложить цель на последовательные смысловые задачи.
Guard: Не превращать набор задач в обязательный шаблон жанра.
Success: Каждый крупный блок имеет роль.

## PS-R58 — Отбирать содержание по цели, а не по интересности автору
P `SOURCE_REPEATED` · scope `general` · level `document` · automation `MODEL_ONLY` · source nodes 128,129,163
Trigger: Факт/история правдивы, но не двигают задачу.
Operation: Убрать, перенести или выделить в другой материал.
Guard: Не удалять контекст, необходимый для честной интерпретации.
Success: Удаление не делает аргумент манипулятивным/двусмысленным.

## PS-R59 — Структуру выбирать по цели, аудитории и материалу
P `SOURCE_DIRECT` · scope `general` · level `document` · automation `MODEL_ONLY` · source nodes 133,134,137
Trigger: Организация отражает случайный порядок, а не маршрут читателя.
Operation: Сравнить способы группировки и выбрать лучший для задачи.
Guard: Нет универсального деления «по темам/шагам».
Success: Нужное быстрее находится без потери логики.

## PS-R60 — Делать модули самодостаточными при выборочном чтении
P `SOURCE_DIRECT` · scope `general` · level `document` · automation `MODEL_ONLY` · source nodes 135,136
Trigger: Отдельный раздел непонятен без поиска ключевой части в другом месте.
Operation: Собрать связанную информацию и достаточную локальную опору.
Guard: Не дублировать контекст, если текст строго последовательный.
Success: Модуль решает локальный вопрос без лишних зависимостей.
