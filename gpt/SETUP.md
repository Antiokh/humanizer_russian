# Настройка Custom GPT

## Название

`humanizer_russian · Русский редактор`

## Описание

Русский редактор, который начинает с механической проверки: сначала выполняет детерминированные проверки, затем при необходимости подключает контекстный слой нормы, живой речи, редакторских школ и идиолекта автора.

## Полная GPT-сборка

Собирайте Custom GPT не вручную и не из отдельных `check.py`/`lint.py`, а одной командой:

```bash
python3 scripts/package_gpt_runtime.py --output dist/humanizer-russian-gpts.zip
```

Архив содержит:

- `Instructions/` — инструкции для настройки GPT Builder;
- `Knowledge/` — тематически собранные справочные материалы;
- `Runtime/humanizer_runtime.py` — автономный механический рабочий контур для Code Interpreter.

`humanizer_runtime.py` автоматически встраивает тот же переносимый пакет Agent Skill, который строится по `skill-package.json`. Поэтому GPT получает полный поддерживаемый набор текущих `check`, `review`, `lint`, `lint-*`, редколлегию, рабочий контур профиля автора и нужные библиотеки и данные без ручной синхронизации Python-файлов.

## Что загружать в GPT Builder

1. Содержимое `Instructions/INSTRUCTIONS.md` вставьте в поле **Instructions**.
2. Все `.md` из `Knowledge/` загрузите в **Knowledge**.
3. `Runtime/humanizer_runtime.py` тоже загрузите в GPT.
4. Обязательно включите **Code Interpreter & Data Analysis**.
5. Web Search включайте только для задач, где действительно нужны текущие факты или внешняя проверка спорной либо изменившейся нормы.
6. Заготовки начала диалога берите из `Instructions/CONVERSATION_STARTERS.md`.

Текущая сборка занимает 15 файлов Knowledge + 1 рабочий файл = 16 загрузок из лимита 20.

## Механический проход внутри GPT

Обычный проход:

```bash
python3 humanizer_runtime.py check --json text.md
```

Глубокий проход:

```bash
python3 humanizer_runtime.py check --extended --json text.md
```

Проверка целостности рабочего контура:

```bash
python3 humanizer_runtime.py verify
```

Список доступных точек входа:

```bash
python3 humanizer_runtime.py list
```

Коды возврата `1`/`2` у `check` могут означать найденные проблемы, а не падение программы. Сначала проверяйте JSON в стандартном выводе.

GPT имеет право говорить, что механическая проверка была выполнена, только если Code Interpreter действительно запустил `humanizer_runtime.py`. Если рабочий контур недоступен, это нужно сказать явно и продолжить только модельную редактуру.

## Что входит в рабочий контур

Точный состав задаёт `skill-package.json`. Сейчас туда входят, в частности:

- `scripts/check.py`;
- `scripts/review.py`;
- `scripts/lint.py`;
- линтеры живого русского, нормы, калек и РКИ;
- линтеры Чуковского, Ильяхова, Галь, Виссон, Розенталя и Голуб;
- редколлегия;
- рабочий контур профиля автора;
- нормализованные библиотеки, профили рецензентов, стили, справочные материалы, схемы и данные слоя дополнительных источников.

Источники дополнительных данных со статусом `PROJECT` не становятся рабочими только из-за наличия общего кода этого слоя.

## Knowledge

В GPT-сборке исходные справочные файлы и нормализованные библиотеки собраны в тематические пакеты. Не нужно вручную выбирать десятки файлов из `references/` и `libraries/`.

`references/native-russian-user-context.md` не попадает в GPT Knowledge: это материал для разработки правил, а не обычный рабочий справочник.

`evals/`, `tests/`, `studies/` и файлы CI в GPT Knowledge не загружаются.

## Agent Skill — отдельная сборка

Для среды с поддержкой Skills остаётся отдельный пакет:

```bash
python3 scripts/package_skill.py --output dist/humanizer-russian.zip
```

GPT ZIP и Agent Skill ZIP — разные дистрибутивы, но исполняемый рабочий контур внутри GPT генерируется из того же белого списка Agent Skill.

## Проверка перед публикацией GPT

CI `.github/workflows/gpt-package.yml` должен:

- дважды собрать GPT ZIP и сравнить архивы побайтово;
- проверить общий лимит загружаемых в GPT файлов;
- запустить `humanizer_runtime.py verify`;
- проверить наличие всех основных точек входа линтеров;
- сравнить JSON и код завершения упакованного `check` с прямым `scripts/check.py` в механическом и расширенном режимах;
- загрузить как артефакт именно проверенный ZIP.

После этого прогоните `gpt/TESTS.md` в GPT Preview.

## Автоматические блокеры результата

Не публикуйте результат редактуры, если:

- изменён факт, причинность или степень уверенности;
- создана реальная языковая ошибка;
- остался надёжный технический `ARTIFACT`;
- модель заявляет о проверке, которой не было.

`NATIVE_WARNING`, `AI_PATTERN`, `STYLE_WARNING`, `AUTHOR_MISMATCH` сами по себе не являются автоматическими ошибками.
