# humanizer_russian

Русский редактор, который помогает сделать текст естественнее — без трюков ради AI-детекторов, намеренной неграмотности и единого «правильного» голоса для всех.

Он не пытается угадать, кто написал текст. Он ищет другое: где фраза звучит переводно, канцелярски, шаблонно, перегруженно или просто не по-русски — и предлагает более естественный вариант, не ломая смысл.

## Зачем ещё один humanizer

Большинство humanizer'ов работают от внешних признаков: убирают тире, дробят предложения, заменяют слова, добавляют разговорность. Иногда текст после такой обработки становится только хуже.

Здесь подход обратный. Сначала сохраняем смысл и нормальный русский. Потом смотрим, что можно убрать, переставить или сказать проще. И только после этого — стилистика.

Русский позволяет многое, чего не любит механический перевод с английского: опускать понятное из контекста, менять порядок слов, использовать частицы, неполные предложения и повтор ради интонации. Поэтому хорошая редактура не сводится к таблице «плохих слов».

Например:

> Это не ошибка в расчёте, а ошибка в исходных данных.

Естественнее:

> Это ошибка не в расчёте, а в исходных данных.

Общий кусок не нужно повторять — его можно вынести за противопоставление.

А здесь, наоборот, ничего дополнять не надо:

> — Кого любит Паша? — Машу.

Ответ понятен из вопроса. Полное «Паша любит Машу» звучало бы тяжелее.

И повтор тоже не всегда ошибка:

> Никогда. Никогда больше.

Если он работает на смысл и ритм, его нужно оставить.

## Два режима

У проекта один движок и два способа им пользоваться.

### Compact

Быстрая проверка для CI, редакторского preflight или обычной работы с текстом:

```bash
python3 scripts/check.py text.md
```

Она собирает механически проверяемые правила из подключённых библиотек и выдаёт короткий результат без «совета писателей» и длинного контекста.

Если нужен более широкий набор мягких сигналов:

```bash
python3 scripts/check.py --extended text.md
```

### Editorial Board

Глубокий режим для случаев, когда полезно увидеть разные редакторские школы отдельно:

```bash
python3 scripts/review.py text.md --style neutral
```

Здесь один фрагмент могут независимо оценить несколько систем: например, правила Норы Галь, Ильяхова, Чуковского и слой живого русского. Если они согласны, видно консенсус. Если спорят — спор не прячется за усреднённым баллом.

Для конкретного проекта можно задать редакционную политику:

```bash
python3 scripts/review.py text.md --style rslive_content
```

Это не «реальная рецензия Норы Галь» или другого автора. Это оценка по формализованным принципам, извлечённым из его работ.

## Книги — это библиотеки знаний

Новые книги не превращаются в ещё один огромный prompt. Каждая книга подключается как отдельный слой знаний.

Из неё извлекаются:

- правила и редакторские операции;
- примеры и контрпримеры;
- то, что можно проверить механически;
- то, что без контекста проверять нельзя;
- связь каждого правила с источником.

Механические проверки работают в обоих режимах. Контекстный слой подключается только там, где без него действительно нельзя решить задачу.

Авторы могут не соглашаться друг с другом. Это нормально. У каждого правила сохраняется источник, а похожие наблюдения разных авторов связываются через общее языковое явление. Поэтому compact может показать одну проблему без дублей, а Editorial Board — разные мнения о ней.

Нора Галь, Максим Ильяхов и Корней Чуковский — первые большие авторские слои, которые развиваются в проекте. Следующую книгу можно добавить по той же схеме, не переписывая весь движок.

## Что для проекта важнее всего

Смысл нельзя приносить в жертву красивой правке. Нормальный русский нельзя ломать ради detector score. Авторский голос не нужно вычищать только потому, что редакторская школа предпочла бы другой вариант.

Поэтому порядок такой:

**смысл → норма → живой русский → голос автора → редакторские школы → анти-калька и AI-паттерны.**

Если текст уже хороший, лучший результат — оставить его в покое.

## Что проект не делает

`humanizer_russian` не определяет авторство текста и не выдаёт «процент ИИ». Он не вставляет ошибки специально, не запрещает нормальные русские конструкции по одному формальному признаку и не превращает советы из книги в обязательную норму языка.

## Как добавить новую книгу

Коротко: сначала книгу нужно нормально разобрать, затем выделить атомарные правила, проверить их на контрпримерах и только после этого решать, что станет линтером, а что останется контекстной рекомендацией.

Подробный процесс описан в [`docs/source-integration-runbook.md`](docs/source-integration-runbook.md) и [`libraries/README.md`](libraries/README.md).
