# Mechanical linter tests

Эти тесты проверяют `humanizer_russian` без LLM-judge, web-поиска и чтения reference-файлов.

Основной корпус: `tests/lint_cases.json`.

Запуск:

```bash
python scripts/benchmark_lint.py
python scripts/benchmark_lint.py --json
```

## Два режима

### `mechanical`

Режим по умолчанию. Через `scripts/check.py` показывает только дешёвые и сравнительно точные surface-checks:

- технические артефакты;
- повтор общей части в противопоставлении;
- механически разорванное перечисление;
- дефис вместо тире в прозе.

В этот режим специально не попадают SVO-lock, общая «AI-лексика», плотность тире, короткие фразы, Q/A-кластеры и другие эвристики с высоким риском false positive.

### `extended`

Тестирует весь текущий набор `scripts/lint.py`. Он нужен для разработки эвристик, но не должен быть обязательным runtime-проходом для каждого текста.

## Типы тест-кейсов

- `must_find` — правило обязано сработать;
- `must_not_find` — правило не должно сработать;
- `clean: true` — выбранный режим не должен вернуть ни одного finding.

Так мы тестируем не только recall на синтетике, но и false positives на нормальном живом русском.

## Принцип

Новый linter-rule нельзя считать готовым только потому, что он ловит пример из документации. Для него нужны минимум:

1. положительный пример;
2. естественный отрицательный контроль;
3. пограничный пример, если правило контекстно;
4. deterministic test в `lint_cases.json`.

Если правило нельзя надёжно проверить механически, оно остаётся в `extended` или reference-слое и не участвует в дешёвом runtime-check по умолчанию.
